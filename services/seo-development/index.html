When SEO Needs Engineering

Most SEO problems are solved with content, keywords, schema, and CMS-level edits. Some aren't. When the fix needs real development — a new build, a migration, a Core Web Vitals overhaul, a custom schema system — we scope it as a custom engagement and coordinate with a trusted software engineer. You stay with one point of contact; the work just gets bigger.

When You'd Need This

The SEO Problems That Aren't Content Problems

Standard retainer SEO handles 90% of what most small businesses need. But some situations require engineering, not editing:

  • You're on a platform that won't let you edit what needs editing (rigid template, no schema support, locked theme)
  • Your Core Web Vitals are failing because of custom JavaScript, server configuration, or architectural issues — not the easy wins
  • You need to migrate from one platform to another without losing rankings
  • Your site is a single-page app or custom framework and Google can't index it properly
  • You want a new site built from scratch — designed around SEO from day one, not retrofitted later
  • You need a custom integration — Search Console API into a dashboard, a schema generator for hundreds of pages, automated GBP posting at scale

These aren't problems a keyword audit solves. They need someone to write code.

What We Scope

The Custom Work We Take On

Custom Site Builds

New sites built from scratch — Shopify, Webflow, WordPress with custom themes, or static HTML — designed around SEO performance from the first commit. Clean markup, fast performance, schema baked in, no retrofit tax.

Platform Migrations

Moving from one platform to another without losing rankings. 301-mapping, canonical preservation, schema migration, and post-launch monitoring. The most common scenario where we save client rankings they'd otherwise lose.

Core Web Vitals Engineering

When image optimization and script deferral aren't enough. Server tuning, build-process optimization, framework-level refactors, and the deeper performance work that separates passing from failing on real user data.

JavaScript SEO

Single-page apps, React/Vue/Angular sites, and heavy client-rendered pages that Google struggles with. Server-side rendering, prerendering, hydration fixes, and the render-debugging work that makes JS-heavy sites crawlable.

Custom Schema Systems

When you have hundreds of pages that need schema and no way to manage it manually. We scope a custom schema-injection system or automated generator tied to your content source.

SEO API Integrations

Custom dashboards, automated reports, Search Console / GA4 / Ahrefs API pipelines, review-feed integrations, GBP automation — anything that needs code to tie your SEO data or workflow together.

How It Works

The Scoping Process

Development work never runs on retainer. Every engagement is scoped and quoted up front.

  • Discovery call — we talk through what you need, what's possible, and whether development is actually the right answer (sometimes it's not, and we tell you that)
  • Written scope — what gets built, what doesn't, what success looks like, rough timeline
  • Fixed-price quote — quoted per project, not per hour, so you know the total before we start
  • Deposit + milestones — typically 50% to start, balance on delivery (or milestone-based for larger builds)
  • One point of contact — you work with Phoenix Method; the engineer handles implementation
  • SEO always stays in scope — the development work lands with SEO already baked in, not added later

The honest version: we don't take on dev work that isn't SEO-adjacent. If you need a general web app, a SaaS product, or something disconnected from organic search, we're not the right shop — but we'll tell you that on the call, not three weeks in.

Frequently Asked

Common Questions

Do I need to be an existing client to book development work?

No. Development is a standalone service. That said, development projects tied to an active retainer usually get the best outcome because the SEO work compounds from day one on the new build.

Can you just fix my Core Web Vitals?

Often yes, inside a retainer — image optimization, script deferral, CMS-level layout fixes. But if your scores are failing because of server config, custom JavaScript, or framework issues, that's engineering work and gets scoped separately.

What platforms do you build on?

WordPress, Shopify, Webflow, static HTML, and Next.js / Nuxt for JS-first builds. We don't pick the platform for you — we'll recommend what fits your needs and budget.

Will the new site rank as well as my old one?

For migrations, the goal is no ranking loss on launch day — that's why we do proper redirect mapping, schema preservation, and canonical handling. For new builds replacing weak existing sites, the new one usually outperforms within 60–90 days.

How long do projects take?

Core Web Vitals engineering: 2–4 weeks. Platform migrations: 4–8 weeks. New site builds: 6–12 weeks depending on size. Custom integrations: 2–6 weeks. We commit to a timeline in the written scope.

What if I just need a small dev change and not a full project?

Small changes (a quick code fix, a single schema deployment, a plugin configuration) usually fit inside a retainer. Ask — we'll tell you honestly whether it's retainer scope or custom scope.
